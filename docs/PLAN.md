# 開発計画（TDD）

各ステップは「失敗するテストを書く → 通す → リファクタ」の 1 サイクル以上で完結する粒度にする。
UI 以外のロジック（ドメイン・Repository）を先に固め、UI は Testing Library で振る舞いをテストする。

## フェーズ 0：土台

- [x] 0-1. Vite + React + TypeScript プロジェクト作成、Vitest + Testing Library 導入、ダミーテストが通る
- [x] 0-2. git 初期化、lint/format（oxlint + Prettier）設定

## フェーズ 1：ドメイン（純粋関数）

- [x] 1-1. 城マスタの型定義と JSON 読み込み（100 件・番号 1〜100 が重複なく揃っていることをテスト）
- [x] 1-2. 記録の型と初期値（未押印・押印日 null・メモ空）
- [x] 1-3. `setStamped(record, true, today)` → 押印済み＋今日の日付（押印済みなら元の日付を残す）
- [x] 1-4. `setStamped(record, false, today)` → 押印日が消える
- [x] 1-5. `setStampedDate` / `setMemo`（未押印・不正な日付では押印日を変えない）
- [x] 1-6. 全体進捗の集計（`xx/100`）。記録帳 `StampBook`（城番号 → 記録、記録なし＝未押印）
- [x] 1-7. 地方ごとのグループ化（番号順）と地方別進捗
- [x] 1-8. 絞り込み（すべて / 未押印 / 押印済み）。城が残らない地方は除き、地方の進捗は地方全体のまま

## フェーズ 2：保存（Repository）

- [x] 2-1. `StampBookRepository` インターフェース定義＋テスト用 InMemory 実装（共通の契約テスト付き）
- [x] 2-2. localStorage 実装（保存・読み込み・未保存時は空・壊れたデータへの耐性：読める記録は使い、元データは退避）
- [x] 2-3. データのスキーマバージョンを持たせる（新しいバージョンは UnsupportedVersionError、古いバージョンはマイグレーションの入口）

- [x] 3-2. 全体進捗・地方別進捗が表示される
- [x] 3-3. 押印済みの城に印が表示される
- [x] 3-4. 絞り込みの切り替え（選択は記録帳とは別に保存して次回も使う）

## フェーズ 4：詳細画面
