# 100名城スタンプ帳 仕様書

インタビュー形式で順次決定した仕様を記録する。決定には ID（D-xx）を振る。
変更する場合は行を消さず「~~旧決定~~ → 新決定（変更日・理由）」の形で残す。

## 1. 前提・利用者

- 利用者: 2 人（1 冊の記録帳を 2 台の iPhone で共有する）。3 人以上での共有は当面不要
- 利用形態: iPhone の PWA（ホーム画面に追加して使用）
- UI 言語: 日本語
- 対象: 日本100名城の 100 城のみ（続日本100名城は対象外）。道の駅は中部ブロックのみ（D-60）

利用シーンの優先順位：

1. **記録帳**（押印記録・進捗）
2. **旅の計画**（次に行く城を探す：近い順の一覧・地図。2 人で 1 冊の記録帳を共有するクラウド同期）
3. 現地で使う（スタンプ設置場所、見どころ）

| D-74 | 新しい / 古いバージョン | アプリが知らない新しいバージョンのデータには触れず、「アプリを更新してください」と表示して変更できなくする。古いバージョンは読み込むときに今の形へ変換する（マイグレーション） |

### 2.8 クラウド同期（2 人で 1 冊の記録帳を共有）

| ID   | 項目               | 決定                                                                                                                                                                                                                                                                                                                                                                                                                      |
| ---- | ------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| D-80 | 始め方             | 共有は使いたいときだけ始める。「共有」ボタンから共有画面（`#/share`）を開く。**共有を始める**: 今の端末の記録をクラウドに上げて新しい記録帳を作り、共有コードを表示する（「コピー」と iPhone の共有シート）。共有中の端末では共有画面に共有コードを表示し、何度でも伝えられる                                                                                                                                             |
| D-81 | 共有コード         | 12 文字（読み間違えやすい `0 O 1 I L` を除いた英大文字・数字）を `XXXX-XXXX-XXXX` の形で表示する（推測できない長さ）。入力では大文字・小文字、ハイフン・空白の有無を区別しない                                                                                                                                                                                                                                            |
| D-82 | 参加               | もう 1 人が共有コードを入力して参加する。合う記録帳がなければ「共有コードが見つかりません」。参加する端末の城の記録は消さずに端末内に残し、共有の記録帳を使う。ホーム画面のアプリと Safari は保存場所が別なので、参加はホーム画面のアプリで行う（共有画面に書いておく）。共有をやめる機能・3 人以上の共有は作らない（機種変更したら新しい端末で同じコードで参加する）                                                     |
| D-83 | 同期               | もう 1 人の変更はアプリを開いている間に自動で反映する。電波がないときも記録でき、つながったときに自動で送る。同じ城（駅）を 2 人が同時に変えたときは、城（駅）ごとに後から保存したほうが残る                                                                                                                                                                                                                              |
| D-84 | 同期の状態         | 「共有」ボタンのところと共有画面に小さく表示する（同期済み／送信待ち／オフライン）。城の記録と道の駅の訪問をまとめて 1 つで表示する                                                                                                                                                                                                                                                                                       |
| D-85 | Firestore の構成   | `books/{共有コード}`: 記録帳の情報（version・作った日時）。`books/{共有コード}/records/{城番号}`: 城ごとの記録（stampedOn・memo）。`books/{共有コード}/michinoekiVisits/{駅の番号}`: 駅ごとの訪問（`visitedOn`。行っていないことにしたら削除せず null）。記録帳ごとにバージョンを持ち、形式・マイグレーションの考え方は端末内と同じ。訪問帳を足しても version（1）は変えない（古いアプリは城の記録だけを同期できる）      |
| D-86 | セキュリティルール | 共有コードを知っている端末だけが読み書きできる。記録帳の一覧・記録帳をまたいだ検索はできない。保存できる形を制限する（城番号 1〜100、押印日・メモ（1 万文字まで）。駅の番号 1〜999、`visitedOn` は null か `YYYY-MM-DD`）。記録帳・記録・訪問は削除できない。ルールは `firestore.rules` に置き、アプリより先に公開する（`docs/deploy.md`）                                                                                |
| D-87 | 道の駅の訪問の共有 | 共有中は同じ共有コードの記録帳に訪問帳も置き、2 人で同じ訪問帳を使う（共有中に記録したものは端末内には入らない）。共有を始めたとき・参加したときに、端末の訪問帳を取り込む: クラウドにまだ記録がない駅だけに端末の行った日を入れ、記録がある駅（行っていないことにした駅を含む）は変えない。取り込めなければ共有を始めない／参加しない。すでに共有中の端末では取り込まない（公開時点で 2 人とも端末に記録がなかったため） |
